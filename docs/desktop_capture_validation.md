# Windows 桌面采集推流链路

## 代码路径

```text
DesktopCaptureSource (FFmpeg gdigrab, BGRA → YUV420P)
  -> LiveSessionController (本地预览 / 视频编码输入队列)
  -> VideoEncoder (H.264)
  -> FlvMuxer
  -> RtmpPublisher
```

主播面板的“采集源”可选择“桌面捕获”。桌面模式不依赖摄像头枚举成功，启动时使用 `gdigrab` 捕获整个桌面；实际画面尺寸由采集源返回，帧率取自面板配置。桌面模式只采集视频，不包含系统声音或麦克风音频。显示器索引和采集偏移字段尚未接入选择逻辑。

采集源在独立线程读取画面，事件队列最多保留 3 帧并丢弃较旧画面。会话工作线程读取事件，更新本地预览，并将帧送入有界视频输入队列；视频编码线程和 RTMP 发送线程分别处理编码与封装发送。队列策略用于控制积压，未给出端到端帧率、延迟或稳定性指标。

## Windows 验证清单

1. 在无摄像头、设备枚举失败，以及有摄像头三种情况下切换“桌面捕获”，检查开播按钮和 RTMP 地址校验。
2. 检查画面预览与 SRS 拉流回看，确认视频尺寸、颜色、鼠标显示、时间戳连续性，以及桌面模式不发送音频。
3. 检查长时间推流、屏幕尺寸变化、停播重启、网络中断和编码速度低于采集速度时的行为。
4. 使用实际日志记录采集帧数、丢帧、编码队列深度、首包和发送异常，验证后再写性能结论。

此文档描述代码路径与待测项，不代表已完成 Windows 端到端验证。
